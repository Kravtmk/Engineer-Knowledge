# Configure AWS EC2 Manually

## Goal

Prepare the Ubuntu EC2 instance for Docker Compose deployment.

This is the manual alternative to:

[[02.Configuration_VM_Ansible]]

Architecture:

```text
AWS EC2
   ↓
Ubuntu Server
   ↓
Base configuration
   ↓
Docker + Docker Compose
   ↓
/home/ubuntu/myapp
   ↓
Ready for CI/CD
```

---

# 1. Connect to EC2

From the administrator workstation:

```bash
ssh -i ~/.ssh/aws.pem ubuntu@EC2_PUBLIC_IP
```

Verify:

```bash
whoami
```

Expected:

```text
ubuntu
```

Check sudo:

```bash
sudo whoami
```

Expected:

```text
root
```

---

# 2. Check System

Check OS:

```bash
cat /etc/os-release
```

Check hostname:

```bash
hostnamectl
```

Check IP addresses:

```bash
ip addr
```

Check routes:

```bash
ip route
```

Check Internet access:

```bash
ping -c 3 8.8.8.8
```

Check DNS:

```bash
ping -c 3 google.com
```

---

# 3. Update System

```bash
sudo apt update
sudo apt upgrade -y
```

---

# 4. Set Timezone

For this lab:

```bash
sudo timedatectl set-timezone Europe/Rome
```

Verify:

```bash
timedatectl
```

---

# 5. Install Base Tools

```bash
sudo apt install -y \
  git \
  curl \
  vim \
  htop \
  ncdu
```

---

# 6. Install Docker

Install Docker and Docker Compose:

```bash
sudo apt install -y docker.io docker-compose-v2
```

Enable Docker:

```bash
sudo systemctl enable --now docker
```

Check:

```bash
sudo systemctl status docker
```

Verify:

```bash
docker --version
docker compose version
```

---

# 7. Docker Permissions

Check:

```bash
sudo docker ps
```

For this lab, Docker commands can be executed with:

```bash
sudo docker ...
```

The CI/CD deployment itself will later run through AWS Systems Manager.

> Membership in the `docker` group effectively provides root-level access to the host. Add the user only if passwordless Docker administration is intentionally required.

---

# 8. Create Deployment Directory

Create:

```bash
mkdir -p /home/ubuntu/myapp
```

Enter:

```bash
cd /home/ubuntu/myapp
```

Create `compose.yaml`:

```yaml
services:
  myapp:
    image: ghcr.io/kravtmk/myapp-deploy-lab:${IMAGE_TAG}
    container_name: myapp

    ports:
      - "8000:8000"

    restart: unless-stopped
```

Create the initial `.env`:

```bash
echo 'IMAGE_TAG=latest' > .env
```

Verify:

```bash
cat compose.yaml
cat .env
```

Check Compose configuration:

```bash
sudo docker compose config
```

The server is now prepared to pull a Docker image from GHCR.

---

# 9. Security Group

GitHub Actions does not need direct SSH access to EC2.

Administrative SSH should remain restricted in the AWS Security Group:

```text
TCP 22 → MY_IP/32
```

Do not open:

```text
TCP 22 → 0.0.0.0/0
```

The deployment path will be:

```text
GitHub Actions
      ↓
AWS API
      ↓
AWS Systems Manager
      ↓
EC2
```

SSH is not part of the CI/CD path.

---

# 10. Final Check

Run:

```bash
whoami
cat /etc/os-release
ip route
docker --version
docker compose version
sudo systemctl is-active docker
ls -la /home/ubuntu/myapp
sudo docker compose config
```

The server is ready when:

```text
Ubuntu EC2 running             ✅
ubuntu user works              ✅
sudo works                     ✅
Network and DNS work           ✅
System updated                 ✅
Docker installed               ✅
Docker daemon running          ✅
Docker Compose installed       ✅
/home/ubuntu/myapp exists      ✅
compose.yaml exists            ✅
.env exists                    ✅
SSH restricted to MY_IP/32     ✅
```
