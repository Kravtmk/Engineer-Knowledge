# Create AWS EC2 Deployment Server

## Goal

Create an Ubuntu EC2 instance that will run the application with Docker Compose.

Architecture:

```text
AWS
 ↓
EC2
 ↓
Ubuntu Server
 ↓
Docker
 ↓
Docker Compose
 ↓
MyApp
```

---

# 1. Create EC2 Instance

AWS Console:

```text
EC2
→ Instances
→ Launch instances
```

Name:

```text
lab-server-1
```

AMI:

```text
Ubuntu Server 24.04 LTS
```

Instance type for the lab:

```text
t3.micro
```

Select or create an SSH key pair.

Keep the private key only on the administrator workstation.

Example:

```text
~/.ssh/aws.pem
```

Never commit the private key to Git.

---

# 2. Network

Use the default VPC for this lab.

The EC2 instance needs outbound Internet access for:

```text
Docker installation
GHCR image pull
AWS Systems Manager
```

A public IPv4 address can be used for administrative SSH during the lab.

---

# 3. Security Group

Administrative SSH should be restricted to the administrator's public IP.

Example:

```text
Type:   SSH
Port:   22
Source: MY_IP/32
```

Do not use:

```text
0.0.0.0/0
```

for SSH.

GitHub Actions does not require SSH access because deployment will use AWS Systems Manager.

Architecture:

```text
Administrator
     ↓ SSH :22
   MY_IP/32
     ↓
    EC2

GitHub Actions
     ↓
AWS Systems Manager
     ↓
    EC2
```

---

# 4. Connect to EC2

Set correct permissions on the private key:

```bash
chmod 600 ~/.ssh/aws.pem
```

Connect:

```bash
ssh -i ~/.ssh/aws.pem ubuntu@EC2_PUBLIC_IP
```

Expected prompt:

```text
ubuntu@ip-...:~$
```

---

# 5. Verify the Server

Check OS:

```bash
cat /etc/os-release
```

Check hostname:

```bash
hostname
```

Check network:

```bash
ip addr
ip route
```

Check Internet connectivity:

```bash
curl -I https://github.com
```

---

# 6. Record Infrastructure Values

The deployment pipeline will later require:

```text
AWS Region
AWS Account ID
EC2 Instance ID
```

Example placeholders:

```text
AWS_REGION=eu-north-1
ACCOUNT_ID=<ACCOUNT_ID>
INSTANCE_ID=<INSTANCE_ID>
```

Do not publish credentials or private keys.

The Account ID and Instance ID are identifiers rather than authentication secrets, but placeholders are preferable in public documentation.
