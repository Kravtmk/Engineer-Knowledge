# Networking Fundamentals

> Networking from a DevOps perspective: understand how traffic moves from one application to another.

---

# 1. Network

A **network** is a group of devices that can communicate with each other.

Examples:

- laptop
- server
- router
- phone
- VM
- container

Basic path:

Client → Network → Server

---

# 2. Network Interface

A network interface connects a host to a network.

Examples in Linux:

- `eth0` — Ethernet
- `wlan0` / `wlp4s0` — Wi-Fi
- `lo` — loopback
- `tailscale0` — virtual interface

A host can have multiple interfaces and therefore participate in multiple networks.

```bash
ip addr

```
# 3. LAN

**LAN — Local Area Network**

A network connecting devices in a limited area.

Example:

192.168.8.0/24

Our home network:

```
Beryl
  │
  ├── T470
  ├── Proxmox
  ├── phones
  └── IoT
```

Devices in the same LAN can communicate directly at L2 if they are in the same broadcast domain/subnet design.

---

# 4. MAC Address

A **MAC address** identifies a network interface at Layer 2.

Example:

```
94:83:c4:72:fe:c5
```

MAC addresses are used for communication inside the local Layer 2 network.

Think:

```
IP  → where is the destination?
MAC → where do I send this frame right now?
```

Check:

```
ip link
```

---

# 5. ARP

**ARP — Address Resolution Protocol**

ARP resolves:

```
IPv4 address → MAC address
```

Example:

T470 wants to communicate with:

```
192.168.8.200
```

It needs the destination MAC:

```
Who has 192.168.8.200?
```

The owner replies with its MAC address.

Linux neighbor table:

```
ip neigh
```

Important:

- local destination → ARP for destination
- remote destination → ARP for gateway

---

# 6. Switch

A **switch** connects devices inside a Layer 2 network.

It forwards Ethernet frames based on MAC addresses.

Simplified:

```
PC ──┐
     │
     Switch
     │
Server┘
```

The switch learns:

```
MAC address → switch port
```

A normal Layer 2 switch does not route between IP networks.

---

# 7. VLAN

**VLAN — Virtual LAN**

A VLAN logically separates one physical Layer 2 infrastructure into multiple isolated Layer 2 networks.

Example:

```
             Managed Switch
             /      |      \
        VLAN 10  VLAN 20  VLAN 30
          HOME   SERVERS    IoT
```

An ARP broadcast from VLAN 10 does not normally enter VLAN 20.

Common design:

```
VLAN 10 → 192.168.10.0/24
VLAN 20 → 192.168.20.0/24
VLAN 30 → 192.168.30.0/24
```

VLAN is Layer 2.

Subnet is Layer 3.

Communication between VLANs requires Layer 3 routing.

---

# 8. IP Address

An **IP address** identifies an interface in an IP network.

Example:

```
192.168.8.129
```

Linux:

```
ip addr
```

An IP address alone is not enough to understand the network.

We also need the prefix:

```
192.168.8.129/24
```

---

# 9. Subnet

A **subnet** defines which IP addresses belong to an IP network.

Example:

```
192.168.8.129/24
```

For `/24`:

```
Network:    192.168.8.0
Hosts:      192.168.8.1 - 192.168.8.254
Broadcast:  192.168.8.255
```

The host uses the subnet to determine:

```
Is destination local?
        │
   ┌────┴────┐
  YES        NO
   │          │
direct     gateway
```

---

# 10. CIDR

**CIDR** describes how many bits belong to the network prefix.

Examples:

|CIDR|Total addresses|Classic usable hosts|
|---|---|---|
|/24|256|254|
|/25|128|126|
|/26|64|62|
|/27|32|30|
|/28|16|14|

Example:

```
192.168.8.0/25
192.168.8.128/25
```

These are two different subnets.

---

# 11. Gateway

A **default gateway** is the next Layer 3 hop used when the destination is outside the local subnet.

Example:

```
T470
192.168.8.129
      │
      ▼
Gateway
192.168.8.1
      │
      ▼
other networks
```

Check:

```
ip route
```

Example:

```
default via 192.168.8.1
```

The gateway is not necessarily `.1`.

`.1` is only a common convention.

---

# 12. Router

A **router** connects different IP networks.

Example:

```
192.168.10.0/24
        │
      Router
        │
192.168.20.0/24
```

The router examines the destination IP and uses its routing table to choose the next hop.

Important distinction:

```
Switch → L2 → MAC
Router → L3 → IP
```

---

# 13. Routing Table

The routing table tells the host where to send IP packets.

Linux:

```
ip route
```

Example:

```
192.168.8.0/24 dev wlp4s0
default via 192.168.8.1
```

Meaning:

```
192.168.8.x → send directly
everything else → send to 192.168.8.1
```

More specific routes are preferred over less specific routes.

---

# 14. DHCP

**DHCP — Dynamic Host Configuration Protocol**

DHCP automatically provides network configuration.

Usually:

- IP address
- subnet mask/prefix
- default gateway
- DNS servers

Example:

```
Laptop
   │
   │ DHCP
   ▼
Router
   │
   └── IP:      192.168.8.129
       Prefix:  /24
       Gateway: 192.168.8.1
       DNS:     ...
```

Without DHCP these settings can be configured manually.

---

# 15. DNS

**DNS — Domain Name System**

DNS resolves names to IP addresses.

Example:

```
example.com
     ↓
93.184.216.34
```

Linux tools:

```
dig example.com
resolvectl query example.com
```

DNS answers:

> What IP address should I connect to?

DNS does not establish the connection itself.

---

# 16. Port

An IP gets traffic to a host.

A **port** helps identify the application/service endpoint on that host.

Example:

```
192.168.8.200:22
              │
              └── SSH
```

Common ports:

|Service|Port|
|---|---|
|SSH|22|
|DNS|53|
|HTTP|80|
|HTTPS|443|

---

# 17. TCP

**TCP — Transmission Control Protocol**

TCP is connection-oriented and provides reliable, ordered delivery.

Before application communication, TCP establishes a connection:

```
Client              Server

SYN       ────────→
          ←──────── SYN-ACK
ACK       ────────→

      ESTABLISHED
```

Then protocols such as HTTP or SSH can exchange data.

---

# 18. UDP

**UDP — User Datagram Protocol**

UDP is connectionless.

It has less protocol overhead than TCP but does not provide TCP's reliability and ordering guarantees.

Used by protocols/applications where this behavior is useful.

DNS commonly uses UDP for many queries, while DNS can also use TCP.

---

# 19. NAT

**NAT — Network Address Translation**

NAT translates IP addressing information as traffic passes through a network device.

Typical home example:

```
T470
192.168.8.129
      │
      ▼
Beryl / NAT
      │
      ▼
upstream network / Internet
```

Many private hosts can access external networks through translated addressing.

NAT and firewall are different concepts.

---

# 20. Firewall

A **firewall** controls which traffic is allowed or denied.

Example policy:

```
HOME → SERVERS     ALLOW
IoT  → SERVERS     DENY
IoT  → Internet    ALLOW
```

Important:

```
VLAN/Subnet → creates boundaries
Router      → connects networks
Firewall    → controls traffic between boundaries
```

Linux examples:

```
sudo nft list ruleset
sudo ufw status
```

---

# 21. Listening Address

A service must listen on an address and port.

Examples:

```
127.0.0.1:8000
```

Only local host.

```
192.168.8.129:8000
```

Only that interface/address.

```
0.0.0.0:8000
```

All local IPv4 addresses.

Check:

```
ss -lntp
```

A firewall rule does not create a listener.

---

# 22. Encapsulation

Application data travels through network layers.

Simplified:

```
Application
    ↓
TCP / UDP
ports
    ↓
IP
source/destination IP
    ↓
Ethernet
source/destination MAC
    ↓
Physical network
```

Useful mental model:

```
Application → WHAT
Port        → WHICH SERVICE
IP          → WHICH HOST/NETWORK
MAC         → WHICH LOCAL NEXT HOP
```

For a remote destination:

```
Destination IP  = remote server
Destination MAC = local gateway
```

The Layer 2 header changes as traffic moves between Layer 2 networks.

---

# 23. Troubleshooting Path

Do not randomly try commands.

Follow the packet:

```
Application
    ↓
DNS
    ↓
Destination IP
    ↓
Route / Gateway
    ↓
ARP / Local next hop
    ↓
Firewall
    ↓
TCP/UDP port
    ↓
Listening service
    ↓
Application
```

Core Linux toolkit:

```
ip addr
ip route
ip neigh

ping
traceroute

ss -lntp
nc -vz HOST PORT

dig NAME
curl -v URL

tcpdump
```

# DevOps Mental Model

When an application is unavailable, ask:

1. Does the host have the correct IP?
2. Is the destination local or remote?
3. Is there a route?
4. Is the gateway reachable?
5. Does DNS resolve?
6. Does TCP/UDP reach the destination?
7. Does the firewall allow it?
8. Is the service listening?
9. Is the application healthy?

The goal is not to memorize networking.

The goal is to follow the packet and prove where it stops.
