# Owners & Permissions

## Overview

Linux permissions control **who can access files and directories and what they can do with them**.

Every file and directory has:

- an **owner**
    
- a **group**
    
- permissions for **owner**
    
- permissions for **group**
    
- permissions for **others**
    

---

## Read Permissions

```bash
ls -l
```

Example:

```text
-rwxr-xr-- 1 alex developers 1200 Aug 16 deploy.sh
```

Breakdown:

```text
-    rwx    r-x    r--
│     │      │      │
│     │      │      └── Others
│     │      └───────── Group
│     └──────────────── Owner
└────────────────────── File type
```

Owner and group:

```text
alex        → owner
developers  → group
```

---

## Permission Types

Linux uses three basic permissions:

|Permission|Symbol|Value|File|Directory|
|---|--:|--:|---|---|
|Read|`r`|4|Read content|List contents|
|Write|`w`|2|Modify content|Create/delete entries|
|Execute|`x`|1|Execute file|Enter/traverse directory|

Directory permissions are especially important.

For example, without `x` permission on a directory, you cannot normally access files through that directory.

---

## Permission Groups

Permissions are divided into three groups:

```text
rwx r-x r--
 │   │   │
 │   │   └── others
 │   └────── group
 └────────── owner
```

Example:

```text
rwxr-xr--
```

means:

```text
Owner   → read + write + execute
Group   → read + execute
Others  → read
```

---

## Numeric Permissions

Each permission has a numeric value:

```text
r = 4
w = 2
x = 1
```

Add them together.

```text
7 = 4 + 2 + 1 = rwx
6 = 4 + 2     = rw-
5 = 4 + 1     = r-x
4 = 4         = r--
0             = ---
```

Therefore:

```text
755 = rwxr-xr-x
644 = rw-r--r--
700 = rwx------
600 = rw-------
```

## chmod

`chmod` changes permissions.

```bash
chmod 644 config.yml
```

Result:

```text
rw-r--r--
```

Another example:

```bash
chmod 755 deploy.sh
```

Result:

```text
rwxr-xr-x
```

Symbolic permissions can also be used:

```bash
chmod +x deploy.sh
```

This adds execute permission.

---

## Ownership

Every file has an owner and a group.

Check them with:

```bash
ls -l
```

Example:

```text
-rw-r----- 1 alex developers 1200 Aug 16 config.yml
```

Here:

```text
Owner → alex
Group → developers
```

---

## chown

`chown` changes ownership.

Change owner:

```bash
sudo chown alex config.yml
```

Change owner and group:

```bash
sudo chown alex:developers config.yml
```

For a directory and everything inside it:

```bash
sudo chown -R alex:developers project/
```

---

## chgrp

`chgrp` changes only the group.

```bash
sudo chgrp developers config.yml
```

## Users and Groups

Show the current user:

```bash
whoami
```

Show UID, primary GID, and group membership:

```bash
id
```

Example:

```text
uid=1000(alex) gid=1000(alex) groups=1000(alex),10(wheel)
```

Show groups:

```bash
groups
```

## Directory Permissions

Permissions behave differently on directories.

### Read (`r`)

Allows viewing directory contents.

### Write (`w`)

Allows creating, deleting, and renaming entries inside the directory.

### Execute (`x`)

Allows entering and traversing the directory.

Example:

```bash
cd /some/directory
```

requires execute permission on the directory.

This is why a file can have correct permissions but still return:

```text
Permission denied
```

One of its parent directories may not allow traversal.

---

## Recursive Changes

`-R` applies changes recursively.

```bash
chmod -R 755 project/
```

```bash
chown -R alex:developers project/
```

Be careful with recursive permission changes.

Files and directories often require different permissions, so blindly applying `chmod -R 755` can give files unnecessary execute permissions.

## Common DevOps Examples

SSH private keys usually require restrictive permissions:

```bash
chmod 600 ~/.ssh/id_ed25519
```

SSH directory:

```bash
chmod 700 ~/.ssh
```

Make a deployment script executable:

```bash
chmod +x deploy.sh
```

Application ownership:

```bash
sudo chown -R nginx:nginx /var/www/app
```

## Troubleshooting Permission Denied

When you see:

```text
Permission denied
```

check:

```bash
whoami
id
ls -l file
ls -ld directory
```

For the complete path:

```bash
namei -l /path/to/file
```

Think in this order:

```text
User
 ↓
Owner / Group
 ↓
File permissions
 ↓
Directory permissions
 ↓
Parent directory permissions
```

---

## Key Concept

Permissions are not only about files.

To access:

```text
/var/www/app/config.yml
```

the user needs appropriate access through the directory path:

```text
/
└── var
    └── www
        └── app
            └── config.yml
```

A permission problem anywhere in that path can block access.
